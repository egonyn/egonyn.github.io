Reflective Shadow Maps - Nina LUC

1. Introduction

Reflective Shadow Maps (RSM) is an algorithm for interactive rendering of plausible indirect illumination in real-time graphics applications. This idea extends the classical shadow mapping technique by enriching the information stored in the shadow map. In addition to depth information, each pixel in the shadow map stores properties such as position, surface normal and reflected radiant flux. These pixels can then be interpreted as visual point lights, allowing them to contribute to the indirect illumination of the scene.

For this final project, I chose to implement the idea presented in the paper Reflective Shadow Maps by Carsten Dachsbacher and Marc Stamminger. The goal of this project is to reproduce and explore this technique by implementing Reflective Shadow Maps using WebGPU. The implementation is built upon the codebase from the assignment done during the course, which provides the basic components of a real-time rendering pipeline.

The objective of this work is, on the one hand, to understand the theoretical principles of Reflective Shadow Maps and their role in approximating global illumination in real time, and, on the other hand, to implement and integrate this technique into a WebGPU-based rendering engine.

2. Implementation using WebGPU

2.1 Project Architecture

The project is implemented using WebGPU and follows a multi-pass rendering architecture designed to progressively compute both direct and indirect illumination. The application is divided into two main parts:

  • CPU-side logic (JavaScript) : responsible for scene management, buffer updates, etc.
  • GPU-side execution (WGSL shaders) : responsible for all rendering computations, including shadow mapping, G-Buffer generation, indirect lighting, and final shading.

The rendering pipeline is composed of several passes executed sequentially each frame:

Pass 1 : Reflective Shadow Map (RSM) Pass

The first pass renders the scene from the light's point of view to generate the Reflective Shadow Map. Unlike a standard shadow map, this pass outputs multiple textures simultaneously using multiple color attachments in the same render pass:

  • World-space position
  • Surface normal
  • Reflected flux

Pass 2 : G-Buffer Pass

The second pass renders the scene from the camera's point of view to generate a G-buffer, storing world-space positions and surface normals. It is later used for screen-space computations of indirect illumination.

Pass 3 : Low-Resolution Indirect Illumination Pass

In this pass, indirect lighting is computed at a lower resolution to improve performance. The indirect lighting is approximated by sampling a subset of pixels from the RSM, treating them as virtual point lights stored in indirectLoResTexture.

Pass 4 : Interpolation Pass

The screen-space interpolation pass reconstructs a full-resolution image by interpolating valid pixels and marking unreliable ones for further computation.

Pass 5 : Final Rendering Pass

Finally, direct lighting is combined with indirect lighting. Depending on the interpolation result, indirect illumination is either reused or fully recomputed for higher accuracy.

Overall, this architecture follows a deferred, multi-pass approach that balances performance and visual quality, while allowing incremental development and debugging of each stage.

2.2 Shadow Mapping Implementation

As a first step toward implementing Reflective Shadow Maps, I began by implementing a basic shadow map technique. The goal of this step was to better understand the rendering pipeline, become familiar with working with multiple rendering passes, and set up the infrastructure required for the Reflective Shadow Map pass.

Initially, I attempted to implement shadow mapping starting from the code I had developed for Assignment 4. However, the lighting model in my implementation was not very stable, which resulted in unconvincing visual results. Because of these issues, I decided to restart the implementation from scratch, this time using the solution of Assignment 4 as a more reliable base. I studied several shadow mapping implementations available online in order to better understand the different rendering passes involved, as well as the use of textures and depth buffers.

This step took a significant amount of time, as I focused on carefully understanding the logic of the algorithm and the structure of the rendering pipeline. Although time-consuming, this phase proved to be essential for gaining a solid understanding of shadow mapping, which is the foundation of Reflective Shadow Maps.

In the end, there is a tiny glitch with the shadow when the animation is triggered at a specific moment. This is likely due to the light placement and frustum handling, but the issue could not be fixed in time.

2.3 Reflective Shadow Map Pass

After implementing the shadow mapping stage, I had a solid foundation to begin implementing the passes required for Reflective Shadow Maps. The next step was to extend the shadow map so that it could store additional information besides depth.

To achieve this, I created separate textures for each additional quantity: worldPosTexture, normalTexture, and fluxTexture, storing respectively the world-space position, the surface normal, and the reflected radiant flux.

I then modified the rsmVertex shader to compute and output the additional required data, and implemented a rsmFragment shader responsible for writing these values into the three color attachments. To ensure proper data transmission between the CPU and GPU, the shadowPass and depth pipeline were also updated, in particular, the configuration of bind group 1 was modified so that the additional textures could be properly bound and passed to the main shadow pass.

2.4 Indirect Lighting Sampling

I implemented the sampling stage by creating a generateRSMSample function along with an associated rsmSamplesBuffer. To simplify the handling of randomness, parts of the sample positions were generated on the CPU and then transferred to the GPU.

Instead of considering all pixels of the RSM, which would be computationally too expensive, a limited subset of pixels is selected. Each selected pixel corresponds to a virtual point light, defined by its position, normal, and reflected flux stored in the RSM. The indirect illumination is then approximated by accumulating the contributions of these sampled pixel lights, taking into account distance attenuation and surface normal orientation.

The first results exhibited noticeable artifacts, particularly strong oversaturation in certain regions. Rather than immediately addressing these issues, I chose to continue developing the full pipeline in order to validate the overall structure of the implementation.

At a later stage, I revisited the indirect lighting computation. I modified the computeIndirectLight function by introducing a condition to discard samples too close to the shaded point: if (dot(xmxp, xmxp) < 0.09) { continue; }. This threshold helps avoid excessive contribution from nearby virtual point lights. A small offset was also introduced to stabilize the lighting evaluation. These modifications significantly improved the visual quality, though some artifacts remain upon close inspection.

2.5 Screen-Space Interpolation

The screen-space interpolation step does not fully follow the method described in the original paper, and some planned improvements could not be completed in time.

The general approach consists of first computing indirect illumination at a lower resolution, then performing an interpolation pass to reconstruct a full-resolution image. Each high-resolution pixel is examined to determine whether its value can be interpolated from neighboring samples in the low-resolution grid, based on geometric consistency criteria such as surface normal similarity and spatial proximity.

If a sufficient number of valid neighboring samples is found, interpolation is performed. Otherwise, the pixel is marked for a full evaluation using the RSM. Unlike the original paper, the quadrilateral-based interpolation scheme and occlusion queries were not implemented. A simpler approach was chosen to still achieve a reasonably efficient and interactive result.

Interpolation validity information is stored in a dedicated texture called needsFullEvalTex, accessed during the final rendering pass to decide whether a pixel should be interpolated or fully evaluated.

However, an unresolved issue remains in the full evaluation step, visible along the edges of the bunny or sphere models, where indirect lighting appears noticeably pixelated. This artifact is likely related to how the full evaluation stage is handled.

3. Results, Conclusion & Future Work

The implementation of Reflective Shadow Maps made it possible to significantly improve the visual realism of the rendered scenes compared to direct lighting only. Without indirect illumination, the scene appears relatively flat, with hard shadows and limited interaction between surfaces. By introducing RSM, indirect light contributions become visible, especially in regions not directly illuminated by the main light source, resulting in softer lighting transitions and a more coherent global appearance.

Most of the core ideas presented in the original paper were implemented, although sometimes in a simplified or slightly different way. The overall pipeline is functional and produces visually convincing results, demonstrating the effectiveness of Reflective Shadow Maps for real-time indirect illumination.

One remaining issue concerns the blending of indirect lighting with the mesh's base color, which does not appear to work correctly and results in a visual inconsistency. It is unclear whether this is a limitation of this implementation or relates to aspects of the original method that were not fully reproduced.

Several improvements could be considered in future work. Refining the interpolation method, particularly by incorporating more sophisticated reconstruction techniques, would likely improve both performance and quality. The paper also mentions combining RSM with soft shadow mapping, which would be of great interest for achieving more realistic rendering. Overall, this project has provided a much deeper understanding of real-time global illumination techniques, WebGPU, and the practical use of multi-pass rendering with textures.
